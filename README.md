# 인생영화 상영표

인생영화(최대 5편)를 넣으면 취향이 비슷한 영화 12편과, 국내 OTT 어디서 볼 수 있는지 한 판에 보여 주는 정적 웹앱입니다. 서버·API·키 없이 `index.html` 하나로 추천이 동작합니다(포스터와 글꼴만 외부에서 불러옴).

## 특징
- 수록작 669편에서 키워드·장르·분위기·**후기 태그**를 합쳐 코사인 유사도로 추천
- **후기 반영**: 영화마다 후기에서 자주 나오는 표현(여운·눈물주의·몰입·호불호 등 15종)을 담았고, "후기에서 이런 말이 많은 영화"를 골라 추천에 반영하거나 "불친절하다는 후기" 등을 피할 수 있음
- 구독 중인 OTT 강조·필터, 분위기 선택, 회피 조건(공포·잔인·150분 초과·애니), "이미 봤어요", 플랫폼 편성표
- 라이트/다크 자동, 모바일 대응

## 포스터
포스터는 [TMDB](https://www.themoviedb.org)에서 불러옵니다. 경로는 `data/posters.json`에 저장되어 있고(키는 저장하지 않음), 아래로 갱신합니다.
```powershell
$env:TMDB_KEY="발급받은_v3_API_키"; npm run posters   # 없는 영화만 받음, --refresh 로 전체 갱신
```
제목·연도로 자동 매칭하며 불확실한 영화는 저장하지 않고 목록으로 출력합니다. 이 제품은 TMDB API를 사용하지만 TMDB의 보증이나 인증을 받은 것은 아닙니다.

## 데이터 검증
### 연도·상영시간·감독 (자동)
`npm run verify`는 영화의 **연도·상영시간·감독**을 외부 자료와 자동 대조합니다. 출처는 Wikidata와 한국어·영어 위키백과이고, 같은 제목의 다른 영화는 감독으로 걸러 냅니다. 내 값이 어느 출처와 4분 안이면 일치, 아니면서 2곳 이상이 같은 값이면 수정 권고, 그 외는 수동 확인으로 표시합니다. 감독판·복원판 때문에 값이 갈리는 영화는 `data/verify-notes.json`에 이유와 함께 예외로 남겼습니다. 새 영화를 넣을 때는 `node tools/verify.js 새영화.jsonl`로 합치기 전에 확인하세요.
- 현재 669편 중 668편이 확인됐고 1편은 예외 메모로 처리했습니다. 이 검증으로 기존 오류 20여 건(상영시간, 연도, 영문 원제, 공식 한국어 제목)을 고쳤습니다.

### 줄거리 (반자동)
`node tools/verify-plot.js`는 줄거리 4줄에서 흔하지 않은 낱말(인물·지명·설정)이 위키백과 줄거리에 있는지 줄 단위로 비교해 **의심 영화를 걸러 냅니다**. 점수는 오류 판정이 아니라 읽을 우선순위이고, 최종 판단은 사람이 위키백과 줄거리를 직접 읽고 합니다.
- 한국어 위키백과 줄거리가 있는 438편은 의심 줄이 걸린 95편과 걸리지 않은 343편을 모두 읽었고, 영어 위키백과로도 약 225편을 읽었습니다. 이 과정에서 줄거리 오류 30편(예: 「스물」 인물 역할 뒤바뀜, 「군함도」 인물 소개, 「써니」 인원수, 「박사가 사랑한 수식」 가족 관계)을 고쳤습니다.
- **한계**: 읽는 일은 제가 위키백과 줄거리 앞부분(한국어 약 520자, 영어 약 480자)과 대조한 것이라, 줄거리 뒷부분의 오류는 놓쳤을 수 있습니다. 자동 점수는 근거 없이 지어낸 줄은 잡지만 인물 이름·역할이 서로 뒤바뀐 오류는 놓칠 수 있습니다. 한국어·영어 위키백과 모두 줄거리가 없는 영화는 검증 근거가 없습니다.
- **줄거리·명대사·후기 태그·OTT·장르 분류는 여전히 제작자의 지식에 의존**합니다.

## 알려진 한계 (꼭 읽어 주세요)
- **OTT 정보는 실시간이 아닌 제작자의 추정**이며 틀릴 수 있습니다. 화면에도 "추정"으로 표기하고 JustWatch 링크를 달았습니다. 신규 추가분(195편)은 특히 검증하지 못했습니다.
- **후기 태그는 실제 리뷰를 수집·분석한 결과가 아니라**, 제작자가 아는 일반적인 평가 경향을 요약한 값입니다. 크롤링·API를 쓰지 않았습니다.
- 추천은 키워드 겹침 기반이라 취향의 미묘한 차이는 반영하지 못합니다.

## 구조
```
index.html          빌드 결과물 (GitHub Pages가 서빙, 직접 수정 금지)
src/template.html   화면·상태·렌더링
src/engine.js       검색·추천 (DOM 비의존, 테스트 대상)
data/movies.json    영화 DB — 수정은 여기서
tools/build.js      template + engine + data → index.html
tools/validate.js   데이터 검증(스키마·어휘·중복)
test/               node:test 테스트
```

## 개발
Node.js 20+ 필요 (의존성 없음).
```bash
npm run validate   # 데이터 검증
npm test           # 검색·추천 테스트
npm run build      # index.html 생성
```
`data/movies.json`을 고쳤다면 `npm run build` 후 `index.html`까지 함께 커밋하세요(CI가 최신 여부를 확인합니다).

### 장르
`primary`(대표 장르 1개)와 `subgenres`(세부 장르 1~2개)는 필수이며 `tools/lib.js`의 어휘 목록에서만 고를 수 있습니다(검증됨). 새 영화를 넣을 때 "이 영화의 진짜 결"을 기준으로 고르세요.

### 줄거리
`synopsis` 필드(필수)는 **정확히 4줄**의 배열입니다. 결말 스포일러 없이 설정과 전개까지만 쓰고, 카드의 "줄거리 4줄"을 펼치면 보입니다. 제작자의 요약이라 세부는 틀릴 수 있습니다.

### 명대사
`quote` 필드(선택)에 대표 대사를 한 줄 넣으면 카드에 표시됩니다. 자막·더빙마다 표현이 다르므로 **확실한 것만** 넣고, 모르면 비워 두세요. 현재 일부 작품에만 있습니다.

### 영화 추가
`data/movies.json`에 한 줄 추가합니다. 값은 공백 없는 한 단어 토큰의 배열입니다.
```json
{"title":"제목","orig":"원제","year":2020,"director":"감독","runtime":120,"genres":["드라마"],"keywords":["가족","성장","일상"],"moods":["잔잔","울컥"],"reviews":["여운","눈물주의"],"ott":["nf","wc"]}
```
- 분위기: 잔잔 울컥 유쾌 긴장 묵직 따뜻 몽환
- 후기 태그: 여운 눈물주의 호불호 몰입 반전충격 잔잔함 유쾌함 불친절 재관람 엔딩논쟁 영상미 연기 음악 불편함 입문추천 (2~5개)
- OTT: nf 넷플릭스 · tv 티빙 · wv 웨이브 · cp 쿠팡플레이 · dp 디즈니+ · wc 왓챠 · at Apple TV · pv 프라임비디오
- 키워드 `잔인`은 추천에는 쓰이지만 취향 키워드 목록에는 나오지 않습니다.

## 추천 알고리즘 (v3)
- **벡터**: 영화 하나 = **대표 장르(1.0)·세부 장르(1.0)**·키워드(1.0)·장르(0.45)·분위기(0.6)·후기 태그(0.5) 가중 벡터. 대표 장르는 13종 중 1개, 세부 장르는 43종 어휘 중 1~2개("시간여행" "연쇄살인" "가족드라마" 등)로, 흔한 키워드만으로는 구분되지 않는 결을 가릅니다. 각 토큰은 **IDF 완화 가중**(흔한 태그 감쇠, 희귀 태그 강조, 0.6~1.8배 제한)을 곱합니다.
- **입문추천 분리**: 후기 태그 `입문추천`은 대중성 신호라 유사도에서 뺐고, "누구에게나 추천받는"을 고를 때만 소폭 가점(+0.06)을 줍니다.
- **여러 편 입력**: 입력 영화마다 따로 코사인 유사도를 구해 `0.7×최대 + 0.3×평균`으로 섞고, 입력 영화마다 최소 2자리를 보장합니다(한 취향에 쏠려 다른 영화가 묻히는 것 방지). 취향 선택(키워드·분위기·후기)은 별도 벡터로 비교해 영화 유사도와 5:5로 섞습니다.
- **다양성 재순위(MMR)**: 12편을 고를 때 이미 뽑힌 영화와 너무 비슷하면 감점(0.2)해 비슷한 작품만 몰리는 것을 막습니다. 같은 감독 가점(+0.08)은 유지합니다.
- 화면의 퍼센트는 상위 12편 내 상대값(66~96)입니다.

### 평가
`npm run evaluate`는 `test/eval-pairs.json`(제작자가 정한 "비슷한 영화" 쌍 42개 + 여러 편 입력 8개)으로 점수를 냅니다. 옵션은 JSON으로 넘깁니다. 예: `node tools/evaluate.js {"mmr":0}`, 기준선은 `{"legacy":true}`.

| 지표 (669편 기준) | v1 | v3 |
|---|---|---|
| hit (한 편이라도 맞힘) | 0.881 | **0.952** |
| mrr (첫 적중 순위) | 0.453 | **0.614** |
| coverage (여러 편 입력 시 입력마다 적중) | 0.375 | **1.000** |
| recall (기대 영화 중 12편에 든 비율) | 0.536 | **0.615** |

평가 세트가 작고 **평가 정답과 장르 데이터를 같은 사람이 만들었기 때문에** 실제보다 낙관적일 수 있으며, 작은 차이는 잡음입니다. 영화를 늘릴수록 후보가 늘어 같은 평가 세트에서도 절대 점수가 내려갑니다(v3 recall: 369편 0.702 → 419편 0.668 → 469편 0.640 → 669편 0.615). 평가 세트에는 내용상 분명히 비슷한 신규 영화 3편을 정답으로 보강했고, v1과의 비교는 항상 같은 영화 수에서 합니다. `npm test`가 v1보다 hit·mrr·coverage가 나빠지지 않는지 지킵니다.
